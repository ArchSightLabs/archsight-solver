# ArchSight Solver 开源路线图

> 本文件只说明当前基线、近期方向、明确非目标和路线维护规则，不承担版本发布记录。当前功能边界以 [功能与适用边界](capabilities.md) 为准，历次版本变化以 [CHANGELOG](../CHANGELOG.md) 为准，发布证据以 `docs/verification/release-*-acceptance.md` 为准。

## 产品定位

ArchSight Solver 是面向结构工程师、高校教师和进阶学习者的开源结构力学求解器工作台。项目不追求“大而全”的工程设计平台，而是把三类典型二维结构分析做成可安装、可验证、可复核、可导出的专业工具：

- 梁系：连续梁、简支梁、悬臂梁。
- 二维平面桁架：典型屋架、桥式桁架、悬挑桁架和教学算例。
- 二维平面框架：门式刚架、显式节点—构件模型、框架梁退化验证和有边界的稳定分析。

核心价值是结果可信、建模快捷、图表清晰、计算书可交付、算例可回归。

## 当前基线

当前公开核心已形成三类分析对象的完整使用闭环：

- Web 工作台：参数建模、模型预览、求解、结果查看和工程导出。
- 计算结果：支座反力、剪力、弯矩、挠度、节点位移、杆件轴力、杆件轴应力等专业指标。
- 工程输出：结构图、荷载图、内力图、挠度曲线、结果摘要、DOCX / XLSX 计算书。
- 数据入口：ASMS-JSON、REST API、CLI、MCP tools、文本模型和公开案例接口。
- 可信证据：输入、结果、来源、SHA-256 摘要和复算规则可进入可信计算包。
- 质量门禁：公开 benchmark、错误契约、后端测试、前端测试、DOCX 三浏览器导出矩阵和视觉回归。

当前仓库基线的公开验证集包含 71 个通过算例：

| 分组 | 数量 | 覆盖重点 |
|---|---:|---|
| 梁系 | 22 | 简支梁、悬臂梁、连续梁、均布荷载、集中荷载、局部荷载和弹性支座 |
| 二维平面桁架 | 18 | Pratt、Warren、Howe、悬挑桁架、平行弦桁架、杆件自重、专项解析验证和反力校核 |
| 二维平面框架 | 26 | 门式刚架、构件荷载、弹性支座、构件集中荷载、模板回归、商业软件对标、坐标变换和框架梁退化验证 |
| 二维框架弹性几何非线性 | 5 | 受压梁柱放大、临界后平衡/稳定分离、Williams / Lee 极限点前路径和 Euler 初始缺陷柱 GNIA |

验证方法与结果分别见 [Benchmark 方法论](verification/benchmark-methodology.md) 和 [公开验证集报告](verification/benchmark-validation-report.md)。

## 路线原则

- 先巩固三类核心模块，不新增第四类分析域。
- 先保证数值可信度和适用边界，再扩展高级分析。
- 先统一模型、结果、导出和测试契约，再优化交互细节。
- 先服务高频工况和可复核算例，再追求泛化建模能力。
- 先保持开源核心轻量可维护，不在 Solver 内置账号、组织、订阅或云协作能力。

当前建设重点是专业建模控制、计算书可信度和契约漂移治理。公开路线只记录可由代码、导出证据链和自动化测试证明的方向，不预告未经评审的版本号或发布日期。

## 近期方向

### 专业建模与结果复核

- 继续收紧材料、支座、节点、跨段、构件和杆件的工程语义与输入诊断。
- 保持基本荷载、工况、组合、包络、关键点和复核点在工作台、API 与导出中的来源一致。
- 高级分析只在模型假定、失败契约和独立 benchmark 同时明确后进入稳定能力。

### 计算书与可信证据

- 保持屏幕图形、DOCX / XLSX 和可信计算包使用同一结果事实与图形适配口径。
- 计算过程、诊断、哈希、结果来源和复算规则应可审计，但不以技术字段淹没工程结论。
- 标准与详细计算书必须保持真实内容分层，失败结果也应保留可解释证据。

### 契约与集成治理

- ASMS-JSON、JSON Schema、OpenAPI、前端 mapper、后端 DTO、CLI、MCP 和导出不得各自定义同一专业字段。
- 项目文件、Host Protocol 和可信计算包的兼容变化必须有版本边界、迁移说明和自动化漂移检查。
- 面向前端接入开发者，本仓库内置的 Reference Host 持续验证加载、修改、保存、刷新重开和只读审阅；该验收不依赖外部商业平台。

### 验证与发布质量

- 持续扩大高价值 benchmark 覆盖，优先补当前能力盲区、解析解、独立刚度法交叉验证和有版本信息的商业软件对标；不以算例数量代替覆盖质量。
- 维护梁系、平面框架、平面桁架的规模梯度性能基线，性能结论只来自可复跑脚本或测试。
- 保持三浏览器 DOCX 图形导出、视觉回归、发行包、容器、SBOM、校验和与回滚证据的发布门禁。

以上方向不等于已承诺的下一版本范围。进入具体版本前，必须另行形成用户价值、兼容边界、验证口径和发布验收记录。

## 模块边界

| 模块 | 当前重点 | 不应偏离的边界 |
|---|---|---|
| 梁系 | 控制截面、复核点、工况/组合来源、计算过程和分层计算书 | 不扩展到桥梁专项、移动荷载/影响线或动力分析 |
| 二维平面框架 | 逐构件关键点、工况/组合包络、计算过程，以及有边界的 P-Delta 和线性屈曲 | 不把当前稳定分析泛化为材料非线性、屈曲后分析或规范设计 |
| 二维平面桁架 | 逐杆轴力、节点位移/反力、工况/组合来源和计算过程 | 不把桁架杆件当作受弯构件，不输出弯矩主指标 |
| 公共能力 | 统一结果事实、可信计算包、项目契约、集成协议和 benchmark 证据 | 不让前端、API、CLI、MCP 或导出器各自发明事实 |

补充专业约束：桁架计算书不得引入弯矩作为主指标。

## 明确非目标

以下方向不进入当前能力承诺；未来如需推进，必须先完成独立价值评审、模型假定、公开契约和验证体系设计：

- 三维杆系、Frame3D 或空间结构求解。
- 影响线/移动荷载、模态/动力分析、非线性材料、接触和屈曲后分析。
- 规范设计、构件承载力设计、施工安全专项业务和工程签审。
- OpenSeesPy 或其他外部求解器作为运行时内核。
- 热—结构耦合、截面温度梯度、瞬态热传导、混凝土徐变松弛和桥梁专用温度场分析。
- 云协作、多用户平台、组织权限、订阅授权和插件化商业生态。
- 地区规范碎片化适配和商业软件式模块堆叠。

## 成功标准

- 外部用户可以按 README 和快速开始完成安装、启动、求解和导出。
- 三类核心模块的典型算例可与参考解、教材解或独立刚度法基线稳定对齐。
- 结构工程用户能清楚看到输入、假定、结果、单位、符号约定和适用边界。
- 贡献者可以通过 ASMS-JSON、benchmark 和测试补充新算例。
- 对外叙事保持清晰：这是聚焦梁系、二维平面桁架和二维平面框架的结构力学求解器，不是缩小版商业设计平台。

## 维护规则

- 新增路线项必须说明对应结构类型、响应指标、验证方式和非目标影响。
- 新增模板、导出字段或 API 字段必须同步检查 README、能力边界、API 参考和测试。
- 跨越 UI、API、CLI/MCP、文本模型或计算书导出的专业字段，先更新 `shared/asms-contract-fields.json` 或对应共享词表，再补前端 payload、后端 schema、公开文档和漂移测试。
- 新增计算书图形或结果插图，先更新 `shared/report-figures.json` 或共享图形目录，再补前端同源 `reportImages`、后端 DOCX 媒体断言和必要的浏览器导出回归。
- 新增内置模板必须同步评估 `data/verification/template_benchmark_map.json`；没有直接 benchmark 时应标注“相近/相关”并记录专项补充需求。
- 新增功能若不能进入 benchmark、测试或可复核样例，应先作为实验能力处理，不写入主路线承诺。
- 路线图只保留阶段方向和验收口径；具体任务拆分放在 issue、PRD 或任务清单中。
