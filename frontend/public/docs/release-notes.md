## v1.9.0

发布时间：2026-09-02

本版让 Solver 在保持独立、开源和本地优先的同时，成为可被 Cloud 完整嵌入的结构计算工作台。嵌入模式由 Solver 自己呈现 Host Portal 顶栏，Cloud 只管理工程、保存、版本和分享，不复制 Solver 的版本、案例、投稿、主题或系统设置。

重点改进：

- 嵌入页头单一化：`embed=1` 使用 Solver 原生的 Host Portal 顶栏，保留真实 Solver 版本、验证投稿、主题和系统设置；文件与云端保存动作通过 Host Protocol 交给宿主。
- 工作区最大化：嵌入态不再叠加独立应用文件菜单，结构建模、计算和结果区获得完整可用高度与宽度。
- 宿主动作为可选能力：Protocol 1.0 新增可选 `requestPortalAction` capability 和 `hostUiActions` allowlist；旧 Host 与旧 Solver 仍可独立回滚。
- 保存闭环保持单一事实：顶栏保存继续复用 `requestSave -> project.saveRequest -> saveResult`，同一 `requestId` 贯穿快照、Cloud revision 与最终回执；只读、重复、保存中和非法动作在协议层拒绝。
- 公开案例边界更安全：嵌入页头从独立 Solver 新标签页打开案例库，避免用公开案例替换并误保存当前 host-managed 云工程。
- 主题与设置归属明确：宿主主题参数只作为初始值，用户可以继续切换主题；系统设置仍由 Solver 自己呈现，不在 Cloud 形成第二套配置源。

兼容边界：

- Host Protocol 版本仍为 `1.0.0`；新能力是可选加法扩展，原五项 required capabilities 不变。
- 不改变结构求解算法、数值结果、项目文件 Schema、计算书或可信计算包格式，不新增数据库。
- Solver 不接触 Cloud token、IAM、租户授权、工程 API 或远程存储；这些职责仍由宿主拥有。
- 完整候选、上线、回滚与公网联调证据见 [v1.9.0 发布验收](docs/verification/release-1-9-0-acceptance.md)。

## v1.8.4

发布时间：2026-09-01

本版把 v1.8.3 发布后的低风险工程修正收口为补丁版本：不扩展结构分析范围或数值算法，重点让错误契约、复核点数据、应用层边界与工程保存语义更稳定，并为独立 Solver 提供明确、可选的云端工作区入口。

发行修订：

- 首次不可变 `v1.8.4` Tag 的 Release 工作流在公开制品创建前被 Trivy 正确阻断，未创建 GitHub Release、未推送 GHCR、未部署生产；公开制品改由不可变发行修订 `v1.8.4-r1` 承载，产品与 Python/npm 包版本仍为 `1.8.4`。
- `v1.8.4-r1` 仅把 Debian `libssl3t64`、`openssl`、`openssl-provider-legacy` 升级到修复 CVE-2026-14456 的 `3.5.7-1~deb13u2`，不改变 Solver 功能、数值结果、项目格式或 Host Protocol 契约。

重点改进：

- 云端入口保持可选：独立 Solver 可按部署配置显示“前往云端保存”，跳转 `cloud.archsight.cn/solver` 登录和管理云项目；嵌入模式不重复显示入口，当前本地工程不会静默上传。
- 保存语义更清楚：工作台把仅作用于当前模型的修改统一称为“应用工程设置”，避免与本地文件保存、宿主保存请求或未来云端保存混淆。
- 错误契约更稳定：未知服务端异常统一返回 HTTP 500；敏感性分析的配置错误继续使用稳定客户端错误，前端先检查 HTTP 状态再消费 JSON。
- 复核数据跨栈对齐：框架与桁架请求的 `reviewPoints` 进入 JSON Schema、OpenAPI、生成 DTO 和 canonical 请求回显，外部调用方不再依赖未声明字段。
- 依赖边界收口：计算与敏感性应用编排直接依赖分析能力，移除经由工作台服务层的反向依赖；README、路线图和架构文档同步明确开源核心与可选 Cloud 宿主边界。

兼容边界：

- v1.8.4 与 v1.8.3 使用相同的求解算法、项目文件、Host Protocol 1.0 和数值结果契约，不新增数据库迁移。
- 未预期的服务端异常由 HTTP 400 修正为 HTTP 500；调用方应继续按 4xx 表示请求问题、5xx 表示服务端问题处理，不应依赖旧的错误分类。
- 未配置云空间地址时入口保持隐藏；开源核心不包含账号、订阅、租户或云项目存储，相关能力仍由可选 Cloud 宿主提供。
- CalculationTrace canonical hash 语义迁移与共回转固定端非零指定位移的 Level 3 数值工作继续 HOLD，不纳入本补丁版本。
- 完整候选验证、镜像、上线与回滚证据见 [v1.8.4 发布验收](docs/verification/release-1-8-4-acceptance.md)。

本版不扩展求解算法或结构分析范围，而是把 v1.8.1 已有的专业计算能力真正交付给普通工程用户：页面、图形、计算过程、快照对比、稳定审查和计算书统一采用中文工程语义；算法 ID、哈希和原始协议字段仍完整保留，但退到技术审计层，不再干扰主阅读路径。

- 计算过程可读：输入规范化、自由度映射、单元处理、整体装配、边界约化和求解步骤显示中文摘要；完整请求哈希、模型哈希、算法标识和内部状态码集中到可折叠的技术审计信息。
- 图形标注降噪：端点、反弯点、局部极值、全局极值等标注可按类别控制，默认优先保留控制性结论；图面与计算书使用同一显示策略，避免屏幕简化而导出重新堆满标注。
- 布局与避碰修复：修复受力变形、内力图、几何非线性过程播放和稳定审查中的裁切、文字重叠及无意义横向滚动；关键数值保持可见，完整数据仍可从点表、计算书和可信计算包复核。
- 结果证据分层：工作台优先显示有界的控制点、复核点和包络记录，避免数百行内部证据直接铺满页面；未经删减的 canonical 证据继续保留在 API、详细计算书和可信计算包中。
- 公开案例与模板本地化：公开工程名称、验证来源、结构形式、方法说明和教学提示统一中文化，不改变 `caseId`、算法 ID、Schema 和结果哈希等机器契约。

兼容边界：

- v1.8.2 与 v1.8.1 使用相同的结构分析域、求解算法和公开契约，不改变数值结果，不新增数据库迁移。
- `corotational_newton_v1`、`initial_stress_v1`、`CalculationTrace@1`、`NonlinearPathTrace@1` 等标识继续作为可复算协议事实保留；只改变其面向用户的呈现方式。

## v1.8.1

发布时间：2026-08-24

本版补齐 v1.8.0 固定初始几何 P-Delta 迭代的专业边界，把二维框架升级为可版本化、可失败、可复算、可教学的弹性几何非线性分析：无缺陷时为 GNA，配置显式或屈曲模态初始缺陷时为 GNIA。材料仍为线弹性，本版不声明弧长后屈曲、材料非线性或规范承载力能力。

核心新增：

- 共回转全 Newton：新增 `corotational_newton_v1`，以当前几何组装完整残差与一致切线，支持确定性残差线搜索、自适应增步、cutback、多重收敛判据和最大接受步数保护；`initial_stress_v1` 继续保留用于 v1.8.0 结果复算。
- 平衡与稳定分离：`equilibriumStatus` 与 `stabilityStatus` 独立报告；荷载控制无法越过极限点时保留最后收敛状态、失败尝试、稳定指标和稳定错误码，不把 Newton 收敛写成安全结论。
- 初始缺陷与荷载路径：支持显式节点缺陷及首阶线性屈曲模态缺陷，记录模态号、幅值、归一化、来源和实际几何偏置；固定预荷载与变量荷载分别推进，不对非线性结果做线性叠加。
- 过程播放与方法比较：新增 `NonlinearPathTrace@1` 和 `MethodComparison@1`；首阶、兼容算法与共回转算法共享请求/模型签名及各自来源哈希，入门、工程、算法三层解释绑定确定性事实。
- 图形与交付证据：路径拐点、残差峰值、最小切线指标、cutback、最后收敛点和终止点均保留数值；标准/详细 DOCX、XLSX 与可信计算包同源记录路径、关键点、缺陷、方法比较和失败证据。
- 可信导出闭环：所选工况/组合先在后端统一投影再生成正文，避免“来源标签正确但表格仍是主结果”；零首阶横向响应不再写出 `Infinity`，而是返回可机读的不可比原因；详细计算书新增共回转当前弦、基本变形、残差方程、切线增量和代表单元状态。
- 失败与比较证据：部分收敛 GNA 作业可由服务端持久化结果生成失败审查材料，保留最后收敛点、失败尝试和路径签名；方法比较补充线性屈曲参考、目标荷载点、不可比原因及四种方法的来源哈希。
- 公开专业验证：公开验证集扩展到 71 个通过算例，新增受压梁柱解析放大、临界后平衡/不稳定分离、Williams toggle 极限点、Lee frame 极限点前多点路径和 Euler 初始缺陷柱解析基准。
- 关键正确性修复：长路径关键帧按全路径分布保留，避免只剩前段与终点；屈曲模态缺陷只叠加相对端点弦的形状残差，避免内部网格重复计算端点插值；模态方向采用确定性平动锚点规范化。

发布验证：

- 后端全量 `736 passed, 2 skipped`，前端单元测试 `444/444`，lint、TypeScript、生产构建和生产依赖审计通过；公开 benchmark `71/71` 通过。
- Chromium 发布闭环 `51/51`、三浏览器 DOCX 导出 `12/12`、三浏览器稳定与关键点矩阵 `15/15` 通过；正式镜像的真实 GNA 教学链路与 Host 集成通过。
- Trivy 中“已有修复版本但未升级”的 HIGH/CRITICAL 为 0；原始扫描仍有 14 个 HIGH、3 个 CRITICAL 未提供上游修复版本，已如实保留在验收记录。SPDX SBOM 包含 109 个包、2959 个文件。
- `v1.8.1` GitHub Release 已发布，7 份公开制品及 `SHA256SUMS` 完成核对；GHCR 与阿里云镜像摘要一致，官方演示站已使用阿里云精确标签上线，v1.8.0 精确镜像与离线归档作为直接回滚点保留。完整证据见 [v1.8.1 发布验收](docs/verification/release-1-8-1-acceptance.md)。

## v1.8.0

发布时间：2026-08-23

本版主题是“二维框架稳定分析 + 可审查计算工作台”。v1.8.0 新增真实 P-Delta 与线性屈曲分析，并把计算过程、工程关键点、方案比较和计算书收敛到同一条证据链，让用户不仅得到结果，还能定位控制位置、复核计算依据并比较一次修改的影响。

核心新增：

- 二维框架稳定分析：新增真实 P-Delta 迭代和线性屈曲特征值求解，分别保留工况/组合、迭代收敛、屈曲模态、残差及接近临界时的失败证据。
- 计算过程与关键点复核：新增 `CalculationTrace@1`、工程关键点、用户复核点和控制包络；请求、模型、结果哈希及单位、符号、精度和控制来源均可追溯。
- 命名快照与方案比较：可保存当前计算快照并比较结果差异，明确区分模型变化、结果变化和不可比状态。
- 图形与计算书同源：梁、框架和桁架图形标注端点、极值、零点、跳变侧别或适用控制对象；屏幕、DOCX、XLSX 与可信计算包共享同一结果事实。
- 分层与失败审查材料：标准版和详细版计算书具有真实内容差异；校验阻断、矩阵奇异或不收敛时可导出失败审查材料，不伪造成功结果。

发布验证：

- 66 个公开 benchmark、独立刚度法、后端与前端全量测试、三浏览器计算书导出、稳定分析、旧项目兼容、发行包隔离安装、Docker 镜像、安全扫描和回滚均已纳入发布门禁；证据见 [v1.8.0 发布验收](docs/verification/release-1-8-acceptance.md)。

## v1.6.3

发布时间：2026-08-07

本版是 v1.6.2 的可靠性与专业验证补丁，不新增结构分析域，不改变 Host Protocol `1.0.0`，也不引入平台、账号或远程存储能力。重点是让首次安装、发布部署、异步作业接入和公开验证证据在更多真实环境下保持可信。

重点变化：

- 修复前端 brace expansion 拒绝服务风险，并把生产依赖与构建工具链分别纳入漏洞门禁；首次克隆和 Windows CI 显式安装、校验 Rolldown 原生可选绑定，避免“本机缓存可构建、干净环境失败”。
- Docker 构建继续固定基础镜像 digest，并允许通过同 digest 的 Public ECR 镜像源规避失效代理缓存；部署脚本只有在 Compose 容器全部进入 `healthy` 后才返回成功，异常状态和超时会输出最近日志。
- `/api/jobs` 的 `X-Tenant-Id` 明确为 `clientJobId` 幂等命名空间，并同步进入 OpenAPI 与 CORS 预检；该字段不承担认证、授权或读取隔离，既有 `jobId` 访问边界不变。

- 这不是新增第四类分析域的版本，而是对三类二维线弹性静力分析对象做交付质量收口：对象建模、文本模型、结果图、DOCX / XLSX 计算书、ASMS-JSON、API、CLI/MCP、benchmark 和公开文档围绕同一套结构对象语义对齐。
- 重点修复 v1.2.0 后暴露出的可信度短板：框架/桁架计算书不能再退回与页面口径不一致的降级示意图，梁系不能因为三类模块统一而丢失“跨段 / 支座 / 荷载”的行业常用建模心智。

工作台建模与交互：

- 三类结构模块统一为“模板 / 基本 / 对象 / 文本 / 表格”五页签；梁系、平面框架和平面桁架共享入口秩序，但保留各自正确的专业对象口径。
- 梁系拆出模板、基本、跨段、支座、荷载、文本模型和表格摘要入口，恢复梁系以“跨段 / 支座 / 荷载”为第一建模心智，并在文本模型中保留支座自由度语义。
- 平面框架补齐节点、构件、材料截面、端部释放、节点弹性约束、荷载、荷载工况和荷载组合编辑入口，支持选中节点直连新增构件，减少手工维护节点连接的摩擦。
- 平面桁架补齐节点、杆件、支座、荷载和文本模型编辑入口，统一杆件编号、节点连接、材料标签和支座节点摘要，避免把桁架杆件误导为受弯构件。
- 对象摘要、基本页、结果页受力变形、荷载编辑器、模板库和计算书选项统一使用共享对象词表；框架使用“构件”，桁架使用“杆件”，梁系使用“跨段 / 支座”，降低跨模块术语漂移。
- 主控建模画布改为按模型规模自适应显示，普通模板默认完整可读，高密度模型才进入低倍缩放与可平移画布；标签布局增加遮挡控制，降低大模型节点、构件/杆件、荷载和尺寸标注混叠风险。
- 结果页收敛为统一的内容区、指标选择器、结果工具栏和工程图预览结构，敏感性分析响应指标从共享结果指标目录派生。
- **受力变形主视图升级**：统一三类分析对象的“受力变形”主视图，支持位移倍率和未变形结构、极值、荷载图层的动态显隐控制；优化实际变形比例下大跨结构内力图和位移图的视觉表现与可读性。
- **视觉风格与信息密度收口**：收紧基本页、系统设置面板、模板库等界面的文本说明与密度，降低用户的视觉断层；统一应用内 SVG 工程图（字重、标号）、ECharts 数据曲线与 DOCX 计算书导出图形的线条粗细（统一向 1.5 基准靠拢），消除视觉割裂。

模板、公开案例与验证集：

- 新增 4 个高频专业模板并写入模板 benchmark 映射：梁系“两端固结均布荷载”“一端固结一端简支”，平面框架“坡屋面门式刚架”，平面桁架“平行弦桁架”。
- 所有内置模板均维护 `data/verification/template_benchmark_map.json` 映射；无法完全对应公开 benchmark 的模板明确标注“相近/相关”，不把相近算例包装成完全验证。
- 公开验证工程继续由 benchmark catalog 生成，覆盖 33 个公开算例：梁系 12 个、平面桁架 8 个、平面框架与框架梁退化验证 13 个；前端“公开案例”和 `GET /api/examples/projects` 使用同一份数据。
- 公开案例、计算书和 API 文档继续携带 `caseId`、验证来源、标准值、容许误差和校核指标，方便第三方平台、教学场景和 Agent Runtime 复核。
- `BM-006` 作为公开的框架梁退化样例保留在验证工程中，但机器预期状态仍为 `REVIEW`；发布说明和验证材料明确其人工复核边界，不把它表述成完全合格样例。

计算书与导出：

- 框架与桁架 DOCX 导出改为使用前端同源工程图 PNG，保留节点、构件/杆件、支座、滚动支座角度、荷载、尺寸、结果图名称和控制值标注，不再混入旧的非 UI 同源曲线或降级结构图。
- 缺少前端同源图片时，DOCX 导出会明确暴露缺图语义；测试锁定“不能伪装成已有工程图”的行为，避免计算书交付材料出现静默降级。
- 计算书图形范围、插图模式、图形 key 和排版选项收敛到共享图形目录和共享导出选项，后端 DOCX 插图断言、前端 `reportImages` 和 Playwright 导出矩阵围绕同一目录验证。
- 大模型计算书插图按节点规模扩展画布，超宽图形自动切换横向页面，降低固定画布导致的裁切、二次压缩和图例拥挤风险。
- 梁系计算书补齐材料与跨段刚度语义，框架/桁架计算书补齐材料截面摘要、支座节点摘要、验证来源证据链和适用边界说明。
- 导出文件名统一按分析对象和导出类型生成，WORD 计算书、XLSX 参数表与前端下载状态使用一致口径。

专业契约、API 与 Agent 集成：

- 新增共享目录：材料、支座、结果指标、计算假定、计算书图形、导出选项和 ASMS 关键字段；前端、后端、API 文档、文本模型和导出逻辑通过共享事实源减少字段漂移。
- JSON Schema、OpenAPI、ASMS-JSON 文档和 MCP 能力说明同步扩展，覆盖公开案例、benchmark 投稿、计算书导出、异步作业和 schema registry 等集成入口。
- 收紧桁架输入契约：拒绝弹性支座、滚动支座法向角、凝聚自由度、转角释放等不符合桁架假定的高级框架字段；桁架支座类型在前端契约中排除不适用的 `fixed` 口径。
- 收敛框架支座类型、节点弹性约束、滚动支座角度、材料默认值和构件连接规则，减少 UI、payload、schema 与计算书之间的专业边界不一致。
- 文本模型解析能力集中到共享基础函数，梁系、框架、桁架分别复用支座解析、荷载解析和对象归一化规则，降低新增语法膨胀风险。
- 本地异步作业文档和行为明确为轻量队列：状态默认写入本地 SQLite，执行由当前服务进程承担；失联时显式失败，不承诺多实例分布式调度或生产级幂等重试。

文档、部署与开发体验：

- 新增结构力学入门文档，覆盖三类分析对象、支座类型、梁系、桁架、框架、符号与方向约定，帮助开发者、学生和贡献者理解当前开源核心的力学边界。
- 更新 README、能力边界、API Reference、ASMS-JSON、Agent 工程流、Agent 集成和公开路线图，明确“可验证、可复核、可导出”的开源核心定位。
- 新增部署模板与运维脚本：Docker Compose 示例、Nginx 示例、部署说明、镜像构建脚本、远程部署脚本和端口清理脚本，补齐公开发布后的私有部署入口。
- 新增 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 和 `AI_CODING_RULES.md`，把项目定位、结构工程术语、中文输出、版本同步和验证要求沉淀为 AI 编码入口。特别固化了强制结构化提交流程（包含 Constraint, Rejected, Directive 等字段）以保证协作上下文透明。
- 前端单元测试入口收敛为 `npm --prefix frontend run test:unit`，计算书图形导出增加 Chromium / Firefox / WebKit 三浏览器矩阵入口，发布构建前自动从 `CHANGELOG.md` 同步前端 release notes。
- 梳理 VS Code 及本地全栈调试（Antigravity）入口，修复调试启动顺序。

质量门禁：

- 后端测试覆盖公开 benchmark、公开案例、JSON Schema / OpenAPI、材料/支座/结果指标共享目录、报告图形目录、计算书文件名、异步作业、文本模型和三类工作台 payload。

- Playwright 视觉链路锁定框架/桁架 DOCX 导出必须携带前端同源图片，并通过媒体字节比对防止同源插图退化。
